# Claude task: polish the voucher journeys

Start from the two-pool voucher PR head. Walk the existing screens on desktop and a narrow phone viewport. Use fixture accounts in Storybook or the repo’s mock-auth preview. Fix concrete navigation, copy, accessibility and state-handling gaps in Client and Admin. The pool design, signing rules and production availability remain governed by the reviewed services and rollout packet.

| Journey | Where to start | Acceptance check |
|---|---|---|
| Earn hub access | Client `views/Home/Garden/Commitment`, `views/Home/WalletSheet/VouchersTab.tsx` | A gardener can go from verified request reward to available TSV to a hub booking without entering the exchange flow. Pending delivery, unavailable exchange and empty capacity have distinct states. Holdings and existing bookings remain usable when only a pool read fails. |
| Exchange member services | Client `views/Profile/ServiceAssets.tsx`, `views/Profile/ServiceIssuerOnboarding.tsx`, `components/Features/Vouchers`, `ServiceLiveExchange.tsx` | A member can find services they offer separately from vouchers they hold. Draft revision, exact pool, obligations and approval are legible before consent. In the exchange review, show the selected TAS pool, input, expected output, fees, and the next booking action. |
| Spend rewards with Green Goods | Client `ServicePromise.tsx` and `ServiceLiveExchange.tsx` | An available Green Goods offer shows the GGV amount needed. A gardener can exchange the TSV shortfall and return to booking. If a member voucher takes two swaps, show each review and receipt and resume at the second after the first confirms. An unavailable listing or offer never looks bookable. |
| Award a past contribution | Admin `views/Garden/Pool/VoucherReserveCard.tsx` and `VoucherAward*`; member receipts in `VouchersTab.tsx` | A steward can review the recipient, issuer reserve, amount and reason, then see the current Safe signing path and recover an uncertain send. Prepared, awaiting authorization and delivered are distinct. The recipient can explicitly load a confirmed receipt without a signature prompt on mount. |
| Steward prepares member terms | Admin `views/Community/components/VoucherIssuerOnboarding.tsx` and `VoucherIssuerDraftEditor.tsx` | The steward can save and send a draft to the named member. An edit that needs new approval says so and does not imply issuance. Member consent identifies the exact version and pool. |

Use the repo’s design primitives and current Client/Admin design guidance. Keep React hooks in Shared, all new copy in English, Spanish and Portuguese, and production availability driven by verified configuration. Use mock data to demonstrate unlaunched offers; changes to minting, approval, quote math, pool admission, live pins or transaction execution require a separate engineering review.

Deliver a focused UI diff, a short list of what changed in each affected journey, and labeled desktop and mobile preview evidence. Exercise keyboard focus, loading, offline or partial reads, rejected signing, expiry and safe recovery where those states occur. Run the affected Client/Admin tests via Bun and use the repo selector for any Shared change.
