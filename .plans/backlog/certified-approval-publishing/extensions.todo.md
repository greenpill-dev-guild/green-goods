# Integration extension checkpoints

**Status:** proposed, not accepted for runtime execution. This file expands checkpoint 14 of
[the core plan](./plan.todo.md) into separate delivery tracks. It also defines a social-sharing
track that can ship independently after its public-data gates pass. Do not turn checkpoint 14
into one multi-provider implementation task. Promote only a selected track into a scoped execution
hub, preserving this hub as the Certified first slice and shared architecture authority.

The public [sync/sharing design](../../../docs/docs/builders/reference/impact-sync-and-sharing-architecture.md)
owns S1/S2/M1/H1/H2. The [provider designs](../../../docs/docs/builders/reference/impact-provider-architectures.md)
own SI1–SI3, B1–B3 and R1–R3; the [action crosswalk](../../../docs/docs/builders/reference/impact-integration-action-map.md)
owns G1–G5 and A1–A4. Partner API discovery is evidence work, not authority to publish test records.

## Delivery order

1. Core phases 0–2: Certified link/configure, history preview, consented publication and repair.
   Historical selection and destination comparison are required functionality in this slice.
2. Core phase 3: supervised Ma Earth display/correction/recovery proof; phase 4: opt-in automation.
3. Social track H: public pages, user-driven sharing and report exports once H1/H2 pass. It does
   not wait for Silvi/Bloom/Regen grants. Start with supported source types, then add other action
   projections behind their domain/readiness gates.
4. GainForest track G: native monitoring evidence and shared AT transport proof. A second proven
   adapter is the checkpoint for extracting shared transport, not a reason to rewrite all domains.
5. Silvi S, Bloom B and Regen R: independently scoped pilots, ordered by partner access and user
   value. No dependency on all other providers being ready. Broader source triggers use track A.

These are independent tracks, not one eighteen-step batch. A contract capability that remains
unknown selects export/manual status or stays blocked. Product decisions about ecological meaning,
public disclosure, grant custody or transaction signing must be accepted before runtime activation.

## Cross-provider completion contract

Each selected integration must demonstrate account/destination authority, exact public preview,
native shape and identity, historical matching, correction behavior and loss-of-response recovery.
Capabilities without native readback stay visibly unverified and cannot enable automatic retries.
A transport abstraction is accepted only when Certified and a second real provider satisfy the
same conformance cases without losing native semantics. Tests must prove useful outcomes, not a
shared class hierarchy. Runtime RED/GREEN and current-SHA receipts belong in each selected track's
owning handoff after promotion; no runtime lane is completed by this planning document.
