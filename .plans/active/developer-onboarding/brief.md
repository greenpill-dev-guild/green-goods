# Simplify development and onboarding

Newcomers face too many runnable aliases and conflicting setup instructions. Green Goods needs a
short product introduction followed by one procedure that a person can hand to any coding agent.

The approved scope is the developer journey: consolidate existing commands, preserve local/live
and hosted/fork boundaries, refresh maintained guides, and make documentation drift detectable.
No dependency upgrades, application features, chain-default changes, deployments, contract
broadcasts, or Plan Hub archival are included.

Success is an understandable README, public and team onboarding paths that preserve existing
work, and a smaller command set whose documented invocations resolve to real scripts.
Implementation is in the working tree. Fresh-install acceptance remains blocked; see [evaluation](eval.md).
