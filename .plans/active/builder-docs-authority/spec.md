# Builder Documentation Authority Spec

## Summary

Replace the builder portal's duplicative implementation prose with a small authored navigation and
workflow layer over deterministic projections derived from code, configuration, ontology, and QA
catalogs. Remove historical and no-value material from the live content tree without creating a
second archive corpus.

## Users

- Primary: builders integrating with or contributing to Green Goods.
- Secondary: coding agents that need reliable codebase navigation without stale shadow truth.
- Maintainers: reviewers who need generated drift and broken authority links to fail before merge.

## Functional Requirements

1. Reconcile all 84 builder pages through one machine-readable migration ledger.
2. Remove 11 historical specifications and 14 no-value pages after tracked consumers move.
3. Distill 15 misplaced pages into code-adjacent runbooks, Plan Hubs, or executable checks.
4. Generate the 17 volatile reference pages from exact checked-in sources.
5. Shrink 26 authored pages only after their generated replacements exist.
6. Preserve Revenue Explorer as the only authored builder specification.
7. Fail CI on broken authority links, invalid generated metadata, and stale generated bytes.

## Research Evidence

- Docusaurus builds every file under `docs/docs`; `unlisted` removes navigation but does not make a
  page non-authoritative or invisible to repository search.
- `docs-audit --ci` currently reports seven broken authority paths but exits successfully.
- Ontology generation already proves deterministic projections are viable, while the old protocol
  status generator writes an unused JSON file with a wall-clock timestamp.
- Package exports, route definitions, deployment artifacts, indexer configuration, workflows, and
  the QA catalog already contain the facts currently copied into builder prose.
- Cookie Jar and Karma integration prose has drifted behind current Envio configuration.

## Authority Contract

- Runtime facts: code, manifests, workflow YAML, deployment artifacts, schemas, and indexer config.
- Semantic facts: `green-goods-ontology.json` plus drift-locked human definitions.
- Non-derivable availability: `green-goods-projections.json`, with exact evidence paths.
- Decisions and rejected alternatives: the owning Plan Hub or durable rationale record.
- Public authored docs: task flows, stable explanations, recovery, and navigation.
- Public generated docs: volatile inventories and status projections.

## Human Judgment Points

- A redirect exists only when the destination is a truthful semantic successor.
- Historical proposals without a selected owner remain in Git history rather than becoming backlog.
- Move means distill unique knowledge, not relocate entire stale files.
- Generated files are committed and reviewable, but wall-clock timestamps are forbidden.

## Non-Functional Constraints

- Do not read `.env` or execute application modules during generation.
- Normalize sources, sort paths, and hash exact source bytes for deterministic output.
- Preserve concurrent PWA and QA changes; treat dirty overlapping files as protected.
- Add no dependencies and no ninth workflow.
- No production runtime, protocol, localization, or offline behavior changes.

## Risks

- Removing a page before rewiring a hidden consumer weakens guidance or CI. Mitigation: exact tracked
  consumer sweep before every removal batch.
- Generators can become another manual database. Mitigation: factual content comes only from existing
  authorities; the manifest stores output routing, not domain facts.
- Concurrent PWA edits can be overwritten. Mitigation: never rewrite protected files wholesale and
  delay the token-audit move and QA-page shrink until those edits settle.
- A historical summary can be mistaken for current truth. Mitigation: mark it historical and prohibit
  current implementation pages from citing it as authority.
