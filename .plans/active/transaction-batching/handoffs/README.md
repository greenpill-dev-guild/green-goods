# Batching handoffs

Start with [publication.md](publication.md), then [continuation.md](continuation.md) for the next objective, current boundaries, remaining product phases, and validation limits. `status.json` owns lane state; `plan.todo.md` owns implementation order.

The detailed [foundation handoff](phase-1.md) and [compatibility follow-up](phase-1-compatibility.md) record the original worktree snapshots. They are historical after a base migration or source change. Lane files are routing aids, not proof of completed work. Do not infer readiness from template receipts or another snapshot's test counts.
