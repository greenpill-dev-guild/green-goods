Common questions about Green Goods, organized by role.

## General

<QuickAnswer question="What is Green Goods?">

Green Goods is an offline-first web app for documenting regenerative work, reviewing submissions, and producing verifiable on-chain records.

</QuickAnswer>

<QuickAnswer question="What chains are currently in scope?">

- Arbitrum One (`42161`): the production network for Season One. <StatusBadge status="Live" />
- Sepolia (`11155111`): testnet for validation and development. <StatusBadge status="Live" />
- Celo (`42220`): early partial deployment (core contracts only, no vault or badge modules, and not indexed). Not used for production workflows yet. <StatusBadge status="In progress" />

</QuickAnswer>

<QuickAnswer question="Can Green Goods work offline?">

Yes. Gardener workflows support offline drafts and queued sync when connectivity returns.

</QuickAnswer>

<QuickAnswer question="Which Green Goods experience should I use?">

- The **public website** ([greengoods.app](https://greengoods.app)) is for exploring public gardens, actions, impact, funding information, and shared terminology.
- The **installed app** is for signing in, joining gardens, documenting work, working offline, syncing, and tracking submissions.
- The **admin dashboard** ([admin.greengoods.app](https://admin.greengoods.app), best on a computer) is for operating gardens: reviewing work, creating assessments, and managing actions, funding, governance, and roles.

Many stewards use both the installed app and the admin dashboard: they document their own work in the app and review garden work in admin.

</QuickAnswer>

<QuickAnswer question="Is Green Goods free to use?">

- Gardener flows are passkey-first and gasless for common submission workflows.
- Steward actions that submit transactions can require network gas.

</QuickAnswer>

<QuickAnswer question="Is uploaded data private?">

No by default. Garden and attestation data is designed to be publicly verifiable. Do not include sensitive personal information in uploads.

</QuickAnswer>

## Gardener

<QuickAnswer question="How do I sign up?">

1. Open [greengoods.app](https://greengoods.app).
2. Choose passkey sign in.
3. Complete device biometric confirmation.

</QuickAnswer>

<QuickAnswer question="Do I need crypto to submit work?">

No. Gardener submission flows are designed to work without wallet management.

</QuickAnswer>

<QuickAnswer question="What if my submission is rejected?">

Use steward feedback to update evidence and resubmit. See:

- [Submit Work](../community/gardener-guide/uploading-your-work)
- [Recovery and Sync](../community/gardener-guide/recovery-and-sync)

</QuickAnswer>

<QuickAnswer question="How do I track approval status and attestations?">

See [Track Status and Attestations](../community/gardener-guide/track-status-and-attestations).

</QuickAnswer>

## Steward

<QuickAnswer question="How do I get steward access?">

Steward permissions are assigned by admins or existing steward governance in a garden context.

</QuickAnswer>

<QuickAnswer question="Can I create a new garden?">

Use [Create Garden](../community/steward-guide/creating-a-garden). Availability depends on your current permissions.

</QuickAnswer>

<QuickAnswer question="Where are endowment and governance workflows documented?">

Use [Funding and Governance](../community/steward-guide/funding-and-governance) to choose between Vaults, Cookie Jars, and signal or conviction pools.

Check [Deployment and Indexer Status](../builders/deployments/status) before announcing those flows as live.

</QuickAnswer>

<QuickAnswer question="How much does steward activity cost?">

Gas cost depends on chain conditions and operation type. Validate current costs in your wallet before signing.

</QuickAnswer>

## Technical

<QuickAnswer question="Is Green Goods open source?">

Yes. Repository: [greenpill-dev-guild/green-goods](https://github.com/greenpill-dev-guild/green-goods)

</QuickAnswer>

<QuickAnswer question="How do I run Green Goods locally?">

```bash
git clone https://github.com/greenpill-dev-guild/green-goods.git
cd green-goods
npm run setup
bun run dev:health
bun run dev
bun run dev:smoke:web
```

Use `bun run dev:prod` only when you intentionally want local browser surfaces
against production Arbitrum, hosted indexer, and hosted agent APIs.

See [Developer Getting Started](../builders/getting-started).

</QuickAnswer>

<QuickAnswer question="How do I contribute?">

Submit a pull request, or say hello in [Discord](https://discord.gg/greenpill) or [Telegram](https://t.me/+N3o3_43iRec1Y2Jh) — accepted work is tracked in Linear. Follow the developer docs in [Developer Hub](../builders/getting-started).

</QuickAnswer>

## Troubleshooting

<QuickAnswer question="App does not load">

- Check connection.
- Refresh and clear browser cache.
- Confirm service availability in [Discord](https://discord.gg/greenpill).

</QuickAnswer>

<QuickAnswer question="Media upload fails">

- Check file size and permissions.
- Retry with stable connection.
- Use offline draft flow if connectivity is unstable.

</QuickAnswer>

<QuickAnswer question="Transaction fails">

- Confirm correct network.
- Confirm wallet balance for gas.
- Retry with updated gas estimate.

</QuickAnswer>
