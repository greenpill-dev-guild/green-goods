# CI & GitHub Actions

16 workflows run the repository's continuous integration. Only CI Gate is a required status: the per-package workflows are path-filtered, so each runs only when its files change and the gate waits for exactly the set a pull request should trigger. Scheduled and manual workflows cover the slow or operator-driven checks that do not belong on every pull request. Purpose and use case come from `scripts/data/workflow-catalog.json`; triggers and jobs are read from the workflow files, and this page says nothing about whether a run is currently passing.

### CI Gate {#ci-gate}

The one required status. It derives the workflows a pull request's changed files should trigger, waits for each to register and report, and fails as soon as one fails or never shows up, so path-filtered workflows cannot silently weaken branch protection.

- **Use it when:** Every pull request on any base branch. Branch protection points here instead of at the per-package workflows.
- **Runs on:** every pull request.
- **Jobs:** `gate`.
- **Required status:** yes, branch protection waits for it.
- **File:** [.github/workflows/ci-gate.yml](https://github.com/greenpill-dev-guild/green-goods/blob/develop/.github/workflows/ci-gate.yml)
