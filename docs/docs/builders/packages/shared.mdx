# Shared

`@green-goods/shared` is the single home for everything the apps have in common: hooks,
providers, stores, protocol data modules, domain types, translations, and the Storybook-backed UI
foundations. If logic could ever serve two surfaces, it lives here first; the client, admin, and
agent packages stay thin on purpose.

## Inside `src`

Shared is layered. Modules talk to the protocol and the network; stores and workflows hold state
and state machines; hooks and providers expose both to React; components render on top. Nothing in
a lower layer imports from a higher one. [`src/MODULES.md`](https://github.com/greenpill-dev-guild/green-goods/blob/develop/packages/shared/src/MODULES.md) is the folder-by-folder map and the
authority on where a new piece goes.

| Directory | What lives there |
|---|---|
| `src/modules/` | Protocol and platform modules, one folder each: `data/` (EAS, gardens, vaults, hypercerts, Karma, IPFS, GraphQL clients), `job-queue/` (the offline-first work queue), `app/` (logger, environment), and the rest |
| `src/stores/` and `src/workflows/` | Client state stores and the XState machines behind multi-step flows |
| `src/hooks/` | Domain hooks by area: auth, garden, work, assessment, vault, cookie-jar, hypercerts, conviction, and more |
| `src/providers/` | App-level providers (auth, chain, query) |
| `src/components/` | Shared UI primitives with Storybook coverage, including the token stories |
| `src/styles/` | The theme and the generated DesignMD tokens every surface reads |
| `src/utils/`, `src/types/`, `src/config/` | Pure helpers (addresses, errors, explorers), the domain types, and the query keys and chain config |
| `src/public-contracts/` and `src/lib/` | The public API contracts the agent serves, and the Hypercerts library bindings |
| `src/commitment-pooling/` and `src/profile-avatar/` | Feature modules too large for one folder family |
| `src/i18n/` | `en.json`, `es.json`, `pt.json`; every user-facing string ships in all three |
| `src/ontology/` | The domain ontology the docs and guards project from |
| `src/__tests__/` | Vitest suites and the test support the apps import through `@green-goods/shared/testing` |

## Run and test

```bash
bun run --cwd packages/shared test
bun run --cwd packages/shared typecheck
```

`bun run --cwd packages/shared check:stories` proves story coverage when UI foundations change;
`bun run --cwd packages/shared test --scope all-configured --coverage` is the fuller pass.

## How it connects

Everything downstream imports shared through its
[declared package exports](./api-index), never `src/**` paths. That boundary is what lets a hook
change ship with confidence: consumers see only the public surface. The flip side is fan-out, so
when you change a hook signature, data shape, or exported utility, validate from the repo root
rather than only inside this package.

## Conventions that will bite you

- All reusable hooks live here. A hook created in `client` or `admin` is a bug by convention.
- **Tailwind classes in shared ship in both apps.** Each app's `index.css` scans shared source
  (`@source "../../shared/src/**/*.{ts,tsx}"`, minus tests, mocks, and stories), so a utility
  written in a shared component is in both bundles. The trap is narrower: a class that appears
  only in a story or a test is not scanned, and a class assembled from strings at runtime is never
  seen, so verify a new utility in the running app, not only in Storybook.
- Query keys come from the central `queryKeys`; ad-hoc query arrays break invalidation.
- Application defaults use `useCurrentChain()` or `DEFAULT_CHAIN_ID`, never wallet chain state.
- Prefer event-driven invalidation over polling.
- New user-facing strings land in all three locale files in the same change, or the i18n gate
  fails.
