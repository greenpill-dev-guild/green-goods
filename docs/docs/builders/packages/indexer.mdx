# Indexer

`packages/indexer` runs the [Envio](https://envio.dev) pipeline that turns contract events into
the GraphQL read models every surface queries. It exists so apps never crawl the chain: gardens,
memberships, vaults, and module state arrive as queryable entities instead of raw logs.

One boundary defines this package: **it indexes protocol events, not EAS attestations**. Work,
approval, and assessment records are read through shared's [EAS data layer](../integrations/eas);
keeping attestations out of Envio keeps the two truth paths independently verifiable.

## Map

| Path | What lives there |
|---|---|
| `schema.graphql` | The entity shapes consumers query |
| `config.yaml` | Which contracts and events are indexed, per chain |
| `src/EventHandlers.ts` and `src/handlers/` | Event-to-entity projection logic |
| `.envio/` | Generated types; regenerate rather than edit |

## Run and test

```bash
cd packages/indexer
bun run check:indexing-boundary
bun run test
bun run build
```

After any change to `schema.graphql`, `config.yaml`, or generated types, run `bun run codegen`
first; skipping it makes failures show up late. Local development uses the Docker-based scripts
from the repo's [full-stack path](../getting-started#path-b-run-the-full-local-stack).

## How it connects

Contract events in, GraphQL out. The [client](./client), [admin](./admin), and [agent](./agent)
read these models through shared's data layer, and the hosted Envio service serves production.
Merging an indexer change does not deploy it; the hosted deployment is a separate, deliberate
step.

## Conventions that will bite you

- Every persisted entity carries a `chainId`, and IDs are composite with the chain to prevent
  cross-chain collisions. One documented exception: `Garden.id` stays the bare garden account
  address for GraphQL compatibility; don't convert it.
- When a relationship changes, update both sides of it.
- `envio dev` preserves the local database. `bun run dev:restart` is a destructive local replay;
  use it only when that's explicitly intended.
- Envio v3 registrations use `indexer.onEvent` and `indexer.contractRegister`; the v2 patterns
  (generated imports, `MockDb`) are gone and must not come back.
