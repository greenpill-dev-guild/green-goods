# Agent

`packages/agent` is the bot and webhook service: it receives inbound platform messages, routes
them through handlers, and serves the public HTTP API. It's how people interact with Green Goods
from messaging platforms without installing anything, and how external systems read public garden
data.

## Map

| Directory | What lives there |
|---|---|
| `src/handlers/` | Inbound message and command handlers |
| `src/api/` | Public HTTP routes (inventoried in the [API Index](./api-index)) |
| `src/services/` | Service dependencies behind stable helper APIs |

## Run and test

```bash
cd packages/agent
bun run test
bun run typecheck
```

Response-shape changes ripple through platform adapters quickly, so run both whenever handlers,
adapters, or service contracts move. `bun run test:coverage` backs security-sensitive changes.

## How it connects

The agent consumes shared hooks and data modules like the other apps, and it's the one surface
that manages wallets on behalf of users, so its security posture is stricter than the rest.

## Conventions that will bite you

- Never store plaintext private keys. Key material flows only through the crypto helpers, and the
  database service is the single persistence boundary: keys are encrypted before insert and
  decrypted on read.
- Logs may carry platform ids, addresses, and transaction hashes, never raw key material.
- Externally triggered actions are rate-limited, and user-facing failures stay generic; internal
  error detail never leaks to users.
- Keep handlers pure where possible and inject the dependencies that need mocking.
