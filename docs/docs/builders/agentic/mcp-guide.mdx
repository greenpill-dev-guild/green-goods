# Agent and MCP Guide

An agent reaches tools in two ways here. MCP servers checked into this repository start with the project for anyone who clones it. Connected services are hosted tools, such as the backlog, telemetry, and deployments, that an agent reaches through a connector in the coding app, signed in by the person using it. Repository guidance says how each may be used.

## MCP servers in this repository

Projected from the checked-in MCP configuration, `.mcp.json`.

| Server | Command | Arguments | Scope | Surfaces |
|---|---|---|---|---|
| brave-devtools | `node` | `scripts/mcp/brave-devtools.mjs` | local-browser-debugging | client, admin, docs, storybook |

### Safety boundary {#safety-boundary}

- WebMCP proof through this wrapper is Brave-only (navigator.modelContext). Do not point it at Google Chrome, Chrome for Testing, Chromium, or Edge.
- The wrapper calls the upstream chrome-devtools-mcp package because that is the protocol package name; the browser executable must still be Brave.
- This isolated DevTools MCP server is public clean-room evidence only; it is not authenticated local QA.
- Use the authenticated Brave extension or visible-desktop path for wallet, passkey, session, installed-PWA, and profile-dependent proof (AGENTS.md § Browser Evidence).
- Do not expose secrets, wallet state, passkeys, local storage, private garden data, telemetry identifiers, or hidden admin actions in prompts or reports.
