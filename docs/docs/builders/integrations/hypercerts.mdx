# Hypercerts

[Hypercerts](https://hypercerts.org) represent an impact claim with ownable fractions. The admin
wizard starts from approved work and records each contributor's share. Claiming and buying those
shares inside Green Goods remain unavailable; the [steward guide](/community/steward-guide/creating-impact-certificates)
explains the current limits. This wizard does not select or certify a commitment-pool cycle.

```mermaid
flowchart TB
  accTitle: Impact certificate minting boundary
  accDescr: The admin wizard selects approved work, prepares metadata and shares, then mints and registers a certificate. Fraction claiming and purchase are outside the current app flow.
  work["Approved work"] --> wizard["Wizard · metadata and shares"]
  wizard --> mint["Mint and register certificate"]
  mint --> record["Public certificate record"]
```

## How it flows

In the admin wizard a certificate starts from work that's already approved, so a claim minted
there traces back to real records. The contract does not enforce that rule: `registerHypercert`
checks operator authority, pause state, and that the claim is minted, and
`createAllowlistAndRegister` takes a metadata URI with no Work or Work Approval UID, so an operator
calling the module directly can register any minted claim. Treat approved work as the
application's constraint, not the contract's.

## Working with it locally

The [fork mode](../getting-started#other-modes) (`bun run dev -- fork`) runs a local fork of
Arbitrum One with the minter and exchange contracts present, so mint flows run locally without
real funds.
