# Environment Management

Green Goods uses one root `.env`. Package-level environment files are unsupported.

## Public contributors

From the repository root, `npm run setup -- --profile isolated` creates a non-secret baseline
only when `.env` is absent. Follow it with `bun run dev:health -- prod` and `bun run dev -- prod`.
This mode uses hosted production APIs. Public browsing needs no team credentials; authentication,
uploads, and privileged actions have additional requirements. Confirmed transactions affect live Arbitrum.

## Team members

Run `npm run setup -- --profile host`, then resolve shared values with `bun run env:sync`.
If no template exists, `bun run env:template:init` creates its shareable shape. 1Password CLI
integration and access to the referenced vault items are required. Synchronization is an explicit
write to the root environment; inspect its impact before replacing existing local values.

Run `bun run env:check` for schema validation and `bun run dev:health` for local prerequisites.
The health command's advanced profiles (`--profile upload`, for example) explain capability-specific
blockers. The default local stack needs Docker and indexer credentials; it targets live Arbitrum.

`.env.schema` owns variable requirements. `.env.template` contains references, not secret values.
Never place secrets in docs, logs, fixtures, package-level files, or generated projections.
Setup reruns preserve the existing `.env`; setup does not merge or repair it.

See [ONBOARDING.md](https://github.com/greenpill-dev-guild/green-goods/blob/develop/ONBOARDING.md)
for profile selection and verification. A successful smoke check is service evidence, not proof of
wallet, passkey, upload, or transaction capability.
